# MoonRecur 0.2.1 维护审计

审计日期：2026-09-12。对象：`shangwuxi/moonrecur`；维护基线：
`aa2f5a3405483d35d413aa4aa2f96a519c4919ed`（0.2.0）。
本记录属于维护者自审，不是第三方认证。范围是既有实现的正确性、输入边界、
工作量和交付验证，不以新增功能数量或提交数量作为实现质量的替代指标。

## 1. 能实际复现的问题

下面的八个见证输入均通过真实 `moon run` 进程在旧版和维护版执行；不是只调用
内部命令分派函数。完整 argv、退出码、原始标准输出和匹配规则保存在
[`quality/cli-before-after.json`](quality/cli-before-after.json)。旧版 0/8 达到预期，
维护版 8/8 达到预期。它们是从已知问题中选择的回归见证，不代表随机发现率。

| 见证 | 旧版实际行为 | 维护后实际行为 | 修复提交 |
| --- | --- | --- | --- |
| 2024-01-15 起，YEARLY、BYMONTH=2,6、COUNT=2 | 返回 0 个日期 | 返回 02-15、06-15 | `3ef105d` |
| 2024-01-30 起，YEARLY、BYDAY=MO、COUNT=2，窗口到 03-01 | 返回 0 个日期 | 返回 02-05、02-12 | `3ef105d` |
| 2024-01-15 起，YEARLY、BYMONTHDAY=1、COUNT=2，窗口到 03-01 | 返回 0 个日期 | 返回 02-01、03-01 | `3ef105d` |
| 2026-01-01 起，DAILY、COUNT=5，排除前两天、limit=2 | 返回 0 个日期 | 返回 01-03、01-04 | `f1740c6` |
| COUNT=4294967297 | 成功接受并规范化成 COUNT=1 | `rule.integer.overflow`，退出码 2 | `a5fa925` |
| nonsense validate --rule FREQ=DAILY | 丢弃 nonsense，成功执行 validate | 报未知命令，退出码 2 | `e7c23cf` |
| --limit 4294967297 | 回绕成 1，成功返回一天 | 拒绝溢出，退出码 2 | `e7c23cf` |
| validate 重复提供 --rule | 静默使用第一项 | 拒绝重复参数，退出码 2 | `e7c23cf` |

根因不是缺少 RRULE 字段：年度筛选错误地保留了隐含月份条件；例外过滤位于
截断之后；十进制累加在乘法前没有边界检查；程序入口搜索已知命令而非保留
实际用户 argv。修复分别位于选择器、集合顺序、数值解析和进程入口，不扩大
为完整日历协议实现。未知命令的标准输出还含帮助文本，脚本明确检查诊断前缀
和退出码；其余七例逐字匹配全部标准输出。

复现时先从基线创建独立 worktree，并在该目录执行 `moon update`：

```sh
git worktree add --detach ../moonrecur-baseline aa2f5a3
# 在 ../moonrecur-baseline 执行 moon update，然后回到当前仓库
python scripts/audit_regressions.py --baseline-root ../moonrecur-baseline --target js --report audit.json
```

不传 `--baseline-root` 时只验证当前版本；CI 在四个目标执行此模式。历史回放
使用原提交源码，不改写当前仓库。报告不把编译失败当成旧版缺陷复现成功。

## 2. 边界与性能审查

| 审查点 | 改动及证据 | 未覆盖或保留的约束 |
| --- | --- | --- |
| 公开可构造结构体绕过构造函数 | `301d4e5` 在展开入口重新验证 Date、窗口和 Rule；直接构造和修改选择器数组有回归测试 | 未将公开字段改成私有；其他 API 的非法直接构造输入不是全面加固的保证 |
| 输入资源预算 | 规则文本 8192 UTF-16 单元；RDATE/EXDATE 各最多 100000 项；原有窗口和 limit 预算保留 | 不是进程级内存或运行时沙箱 |
| 稀疏规则逐日扫描 | `58434b0` 跳过不活跃周期；白盒用例实际计数 37 个候选 | 旧路径 366001 次由逐日循环推导；未测耗时，不声称提速 9892 倍 |
| 日期跳转安全 | 回归覆盖星期锚点、月末、闰年、9999 年上界；1 月 31 日不会被夹紧到 2 月末 | 稠密规则仍按日枚举；扫描跨度仍从 DTSTART 计算 |
| 例外集合和占用排序 | `f1740c6`、`5001ee4` 移除插入排序；相等区间保持原标签顺序，不修改输入数组 | 所有冲突对输出最坏 O(N²)；合并标签累计拼接仍可能有二次开销 |
| 公共 API | 对比基线与维护版两个 `.mbti`，仅末尾空行变化，公开签名未变 | 更严格拒绝非法输入是有意的行为改变，不能称所有行为完全兼容 |

## 3. 独立对照与交付验证

- `python-dateutil 2.9.0.post0` 独立计算 800 个固定输入的期望日期序列；同一组
  在基线 692 通过、108 失败，维护版 800 通过。108 是失败用例数，不是 108 个
  独立缺陷。数据摘要和复现命令见 [QUALITY.md](QUALITY.md)。
- 根包 66 个测试组；其中完整 400 年公历周期检查 146097 个日期，200 组合成
  忙闲日程与逐日占用模型比较。未测路径覆盖率，不用日期数量充当测试组数量。
- CI 运行 `34700555074`，源码提交 `3a904b89429f0c3a10cb67af3aaa30a76ef94d88`，
  四个目标 wasm-gc/wasm/js/native 均通过检查、构建、66 测试组、800 对照和
  10 真实 CLI 用例。该运行先于本审计脚本；新增 8 个见证由后续 CI 单独执行。
- native 的对照 JSON 从该运行制品下载，保存为
  `quality/dateutil-native.json`；本地缺少 C 编译器，未声称本地执行 native。
- 8 个见证与 10 个 CLI 验收存在交集，不相加宣称 18 种独立缺陷。
- 本次未执行 MoonCakes 发布；GitHub 发布不能代替包仓库发布。

对照仅覆盖共同支持的日期子集，不支持时区、小时、序数星期、BYSETPOS 和完整
ICS。WEEKLY+BYMONTHDAY 是现有过滤扩展，非 RFC 允许的组合，已明确记录且不纳入
dateutil 对照。CI 使用 latest MoonBit，并记录工具链版本；后续工具链漂移仍是
维护风险，不能承诺任意将来版本自动兼容。

## 4. 提交审查口径

基线之后的七个实现提交分别处理年度语义、例外顺序、整数解析、公开输入边界、
周期扫描、区间排序和 CLI 入口。另三个提交分别增加独立对照、CI 和发布文档；
本审计提交补充可复现的前后行为证据。每项都有对应文件变更，不包含空提交，
不拆分空洞文案凑数量。文档和测试是维护交付的一部分，但不冒充功能修复提交。

结论：此次维护有可重复验证的旧版失败和维护后通过证据；未发现需要为凑改动量
而增加的新功能。上述范围以外的协议能力、性能上界和恶意输入行为不作无缺陷
保证，是否符合赛事最终审核仍由评审决定。
